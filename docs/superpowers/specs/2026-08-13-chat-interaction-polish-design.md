# Chat Interaction Polish — 设计

## 状态

已确认，等待用户 review spec 后进入 implementation plan。

## 背景与问题

当前聊天工作流已经具备多会话、变更检查、follow-up queue、rollback 和基础文件引用，但两个关键交互仍有明显割裂：

1. 用户问题气泡缺少面向会话恢复的操作。中断回答后，用户无法直接复制原问题，也无法基于该问题快速重提。
2. 图片输入仍以路径文本的形式暴露给用户。无论是粘贴图片还是从文件夹选择图片，输入框都不会显示附件预览，也无法在发送前删除单张图片。

这些问题共同影响两个核心体验：

- **恢复与重试**：会话中断后，应能自然地从当前上下文继续提问，而不是手动复制粘贴。
- **可见与可控**：代码改动和图片附件都应以界面对象存在，而不是隐藏在内部路径或模糊措辞里。

## 目标

1. 为“中断的用户问题”提供 hover 级 `Copy / Edit` 操作。
2. 将图片粘贴与选图升级为可预览、可删除的附件托盘，不再把绝对路径写进输入框。
3. 补齐剪贴板图片粘贴能力，保证剪贴板图片与文件夹选图都能以统一附件方式展示。
4. 保持现有 rollback、queue、插队、runtime 启动和文件引用能力不被打断。

## 非目标

- 不重做整套 Timeline 布局
- 不把所有历史用户消息都做成可编辑
- 不新增 rollback 相关能力或回滚范围
- 不把普通文件引用也改造成统一附件系统
- 不新增插队或 queue 调度规则
- 不新增多模态协议；发送层继续复用现有路径引用能力

## 方案选择

已确认采用 **方案 A：Hover + 附件托盘**。

原因：

- 与现有 `Timeline` / `Composer` 结构最接近
- 保持聊天主流程轻量，不引入右侧动作面板
- 可以在最小改动下承接“编辑重提”和“图片附件预览”两类能力

## 功能规格

### 1. 中断问题的 Copy / Edit

#### 触发范围

仅对“**已发出但中途终止**”的那条用户消息显示 hover 操作：

- `Copy`
- `Edit`

普通历史用户消息不显示 `Edit`，避免时间线中的编辑入口泛滥。

#### Copy 行为

- 点击后复制该用户消息的纯文本内容
- 不修改当前输入框文本
- 成功后可使用轻量 toast 或静默成功，不要求额外 modal

#### Edit 行为

- 点击后，将该条用户消息文本回填到 `Composer` 输入框
- `Composer` 进入“编辑重提”状态，界面可用轻提示说明当前正在重提一条中断问题
- 原始中断问题气泡保留在 Timeline 中，不原地替换

#### 编辑后发送

- 发送时作为一条**新的用户消息**追加到当前会话
- 沿用当前会话上下文，不新建会话
- 若当前存在 follow-up queue，不清空 queue
- queue 与插队行为沿用现有实现，本次不新增新的发送优先级规则

#### 取消编辑

- 用户手动清空或取消“编辑重提”状态后，输入框恢复普通发送模式
- 取消编辑不影响 queue、不影响当前会话内容

### 2. 图片粘贴 / 选图 / 预览

#### 支持入口

- 粘贴图片到输入框
- 从文件夹选择图片

#### 预览区

在 `Composer` 输入框上方新增附件预览托盘：

- 支持多张图片
- 每张显示缩略图
- 每张右上角显示 `x` 删除按钮
- 删除后立刻从待发送附件中移除

#### 复制图片

- 对话区中的图片应支持直接复制
- 复制来源不限于“粘贴进来的图片”还是“从文件夹选的图片”
- 优先复制图片本体；若系统层面不支持，再退回复制该图片文件路径并提示

#### 输入框行为

- 图片不再以绝对路径文本写入 textarea
- textarea 只展示用户实际输入的问题文字
- 普通文件选择仍保持现有路径引用逻辑，不纳入图片托盘

#### 发送行为

- `Composer` 维护独立的 `attachments: ImageAttachment[]`
- 提交时将图片附件作为独立元数据传给 `App`
- `App` 在发送层把这些附件转换为 runtime 当前可识别的内部图片引用
- 用户在 UI 中看不到绝对路径，但发送层继续复用现有文件引用能力

#### 附件继承规则

- 普通新问题发送后，成功提交即清空当前附件托盘
- 对“编辑重提”的消息，不自动继承旧问题的图片附件
- 如果用户要带图重提，需要重新粘贴或重新选择图片

## 架构与组件边界

### `src/renderer/components/Timeline.tsx`

负责：

- 为目标用户消息增加 hover 级 `Copy / Edit`
- 为中断问题保留最小 hover 操作，不扩展到图片消息动作

不负责：

- 管理输入框文本
- 管理图片附件

Timeline 只抛出明确事件，例如：

- `onCopyUserMessage(messageId, content)`
- `onEditInterruptedMessage(messageId, content)`

### `src/renderer/components/Composer.tsx`

负责：

- 管理输入框文本
- 管理“编辑重提”状态
- 管理图片附件列表与预览
- 处理图片粘贴、删除、发送后清空
- 处理剪贴板图片粘贴

不负责：

- 判断某条 Timeline 消息是否允许编辑

### `src/renderer/App.tsx`

负责：

- 连接 Timeline、Composer 与会话发送链路
- 将 Timeline 的“编辑中断消息”事件转为 Composer 状态
- 保证“编辑重提”走当前会话、当前 runtime
- 统一把 `attachments` 转成发送层内部图片引用
- 复用现有 queue 与插队行为，不改变其规则

### `electron/piHost.ts`

负责：

- 继续提供 clipboard 支持
- 在需要时执行粘贴图片的本地临时文件落盘辅助逻辑

不负责：

- 管理 hover 展示
- 管理输入框附件预览

## 数据流

### 中断消息编辑重提

1. Timeline 识别出“可编辑的中断问题”
2. 用户点击 `Edit`
3. Timeline 抛出事件给 `App`
4. `App` 设置 Composer 的“编辑重提”状态并回填文本
5. 用户修改后点击发送
6. `Composer` 将文本交给 `App`
7. `App` 以当前会话、当前 runtime 立即发送
8. queue 保持不变，等当前回答结束再继续消费

### 图片附件发送

1. 用户粘贴图片或从文件夹选择图片
2. `Composer` 将其归一为 `ImageAttachment[]`
3. 预览托盘展示缩略图
4. 用户删除某张图时，仅从 `attachments` 中删除该项
5. 若图片来自剪贴板，renderer 通过 host 将图片内容落盘为临时附件
6. 发送时 `Composer` 提交文本与 `attachments`
7. `App` 将附件转换为内部图片引用，拼入本次发送 payload
8. 发送成功后清空附件托盘

## 状态模型

### 编辑重提

新增一类临时 UI 状态：

- `idle`
- `editingInterruptedMessage`

`editingInterruptedMessage` 至少包含：

- `messageId`
- `originalText`
- `draftText`

该状态仅存在于 renderer，不落盘，不参与 session 恢复。

### 图片附件

新增 renderer 级附件结构：

```ts
type ImageAttachment = {
  id: string;
  kind: "image";
  path: string;
  previewUrl: string;
  source: "paste" | "picker";
  name: string;
};
```

说明：

- `previewUrl` 仅用于本地预览
- `path` 仅供发送层内部转换使用
- 此结构不直接暴露给 Timeline

## 错误处理

### 消息复制

- 剪贴板失败时给轻提示
- 不阻塞其他操作

### 编辑重提

- 若目标消息已不再满足“中断问题”条件，忽略旧入口并提示状态已变化
- 若发送时当前 tab runtime 不存在，继续沿用现有 `ensureActiveTabRuntime()` 逻辑

### 图片附件

- 非图片粘贴：不进入附件托盘
- 文件读取失败：提示“图片读取失败”
- 本地图片不存在：发送前校验并提示，不提交空引用
- 剪贴板图片落盘失败：提示“图片读取失败”

## 测试策略

### Timeline

- 仅目标中断消息显示 `Copy / Edit`
- 普通用户消息不显示 `Edit`
### Composer

- 图片粘贴进入附件托盘
- 选图进入附件托盘
- 多图预览与单张删除
- 剪贴板图片粘贴成功与失败分支
- 发送成功后清空附件
- 编辑重提状态可进入、可取消、可发送

### App 集成

- `Edit -> Send` 走当前会话立即发送
- queue 在编辑重提后仍保留
- queue / 插队沿用现有行为，不发生回归
- 附件在发送层被转换成内部图片引用

### Host

- 剪贴板图片落盘辅助逻辑可用

## 实现顺序

1. 中断消息 hover 的 `Copy / Edit`
2. `Composer` 图片附件预览、粘贴与发送整合

该顺序先处理最小界面行为，再改 `Composer` 数据结构，可降低联动风险。

## 兼容性与迁移

- 不修改历史 session 数据格式
- 不要求迁移现有 Timeline item schema
- 图片附件为 renderer 临时态，不落盘
- 普通文件引用与 `@` 文件选择逻辑保持现状

## 验收标准

1. 中断会话后，目标用户问题 hover 可见 `Copy / Edit`
2. 点击 `Edit` 后可从当前会话重新提问，原消息保留
3. 粘贴或选择的图片会显示在输入框上方，可单张删除
4. 输入框支持直接粘贴剪贴板图片
5. 输入框不再显示图片绝对路径
6. 发送成功后附件托盘清空
